# ADR-0003: Платёжные шлюзы: hosted-страницы, webhook как источник истины, HTTP вне транзакций

Дата: 2026-07-06 · Статус: принято

## Контекст

PCI DSS scope должен быть минимальным (COMPL-03), платёжный провайдер может
быть медленным/недоступным, а статус оплаты должен быть достоверным (PAY-03).

## Решение

1. **Карточные данные не касаются бэкенда**: monobank (UAH) и Fondy (EUR)
   работают через hosted-страницы — бэкенд создаёт инвойс и получает URL.
2. **Webhook — источник истины**: редирект пользователя не меняет статус.
   Callback проверяется HMAC-подписью (fail-closed: пустой секрет = отказ),
   дедуплицируется по `externalEventId` и проходит валидацию переходов
   статусов (SUCCEEDED→FAILED невозможен).
3. **HTTP вне транзакций** (ARCH-10): создание платежа — это TX(создать
   локальную запись) → HTTP к шлюзу (с таймаутами) → TX(применить результат).
   DB-коннект не удерживается на время сетевого вызова.
4. Зависшие платежи истекают по TTL (job), заказ возвращается в CREATED для
   повторной попытки.

## Последствия

- (+) Минимальный PCI-scope; подделка callback невозможна в дефолтной
  конфигурации; пул коннектов не исчерпывается при деградации шлюза.
- (−) Между TX1 и TX2 возможна временная несогласованность (платёж CREATED
  без результата шлюза) — закрывается expiration-джобой.

## Альтернативы

Прямой card-API (расширяет PCI-scope — отклонено), сага/outbox (оправдано при
переходе на брокер сообщений; текущий масштаб покрывается TTL-джобами).
