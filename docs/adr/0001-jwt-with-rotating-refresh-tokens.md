# ADR-0001: Stateless JWT + серверные refresh-токены с ротацией

Дата: 2026-07-06 · Статус: принято

## Контекст

API должно быть stateless (горизонтальное масштабирование, PERF-01), но
long-lived токены без отзыва — риск: украденный токен живёт до истечения.

## Решение

- Access-токен — JWT (HS256, 15 минут, `iss`/`aud` проверяются), секрет только
  из окружения; приложение не стартует без него вне dev-профиля.
- Refresh-токен — opaque, хранится в БД **только как SHA-256 хэш**, живёт 7 дней.
- Ротация: каждый refresh выдаёт новый токен и отзывает старый. Повторное
  использование отозванного токена трактуется как компрометация — отзывается
  вся цепочка пользователя (reuse detection).
- Logout и смена пароля отзывают все refresh-токены; отключённый аккаунт
  не проходит JWT-фильтр даже с живым access-токеном.

## Последствия

- (+) Горизонтальное масштабирование без session store; компрометация БД не
  даёт replay refresh-токенов; кража refresh-токена обнаруживается.
- (−) Access-токен нельзя отозвать раньше 15 минут (осознанный компромисс;
  blacklist потребовал бы Redis).

## Альтернативы

Cookie-сессии (нарушает stateless), RS256 (оправдан при нескольких сервисах,
пока один издатель и один потребитель — HS256 проще и безопаснее в управлении).
